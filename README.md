# Localy

Анонимный чат для локальных сообществ: университетов, школ, районов, микрорайонов и жилых комплексов Бишкека. В чатах пользователи видны только как **Аноним #N** — имя и почта никому не показываются.

## Возможности

**Для пользователей**
- Лендинг `/welcome` для новых посетителей: заголовок, анимированный пример чата, счётчик сообществ, преимущества и кнопка «Начать». Без входа любая закрытая страница ведёт на него.
- Регистрация в три шага (город, места, аккаунт) и вход (JWT access-токен + refresh в httpOnly cookie).
- Места можно выбрать поиском по спискам или по карточкам «Рядом с вами» после разрешения геолокации; автоматическое вступление в городской чат.
- Чат по комнатам сообщества (`#общее`, `#объявления`, `#события`, `#бюро находок`, `#мемы`) в реальном времени (Socket.io).
- Ответы на сообщения, реакции, эмодзи, фото (Supabase Storage), редактирование и удаление своих сообщений.
- Личные сообщения `/dm`: анонимная переписка один на один, можно отправлять фото (то же листание и увеличение). Галочки: одна означает «отправлено», две «прочитано» (обновляются сразу, когда собеседник открывает диалог). Запрос отправляется из чата кнопкой «Написать лично», собеседник принимает или отклоняет его, есть блокировка и настройка «Принимать личные сообщения» в профиле.
- Счётчики непрочитанных у каждой комнаты, у сообщества в переключателе, на кнопке меню и в заголовке вкладки; обновляются в реальном времени.
- Фото можно выбрать из галереи или снять камерой (кнопка камеры на телефоне). Перед загрузкой фото сжимается на устройстве (до 1600 px по длинной стороне, JPEG), поэтому подходят и большие снимки до 25 МБ.
- Просмотр фото на весь экран: листание по всем фото комнаты (свайп, стрелки, клавиши), увеличение щипком, двойным тапом и колесом мыши, закрытие свайпом вниз; кнопка «Сохранить»: на Android и компьютере файл скачивается, на iPhone открывается системное меню «Поделиться» («Сохранить изображение»).
- Пересылка сообщения в другую комнату или сообщество (только свои) с пометкой «Переслано из …»; фото не копируется, используется тот же файл.
- Закреплённые сообщения, поиск по сообщениям комнаты, «Непрочитанные сообщения» с прокруткой к первому непрочитанному.
- Индикатор «печатает», очистка чата «у себя».
- Отметка сообщения как события и список предстоящих событий сообщества.
- AI Summary — краткая сводка последних сообщений комнаты (Gemini).
- Геолокация: кнопка «Найти рядом со мной» сортирует сообщества по расстоянию (координаты нигде не сохраняются, расстояние считается в браузере).
- Страница профиля: редактирование имени, список сообществ с кнопкой «Выйти», выход из аккаунта. Адаптирована под телефон.

**Для администраторов** (`/admin`)
- Управление пользователями (просмотр, удаление).
- Управление сообществами (создание, редактирование, статус, координаты, удаление).
- Жалобы на сообщения: просмотр контекста, действия модератора, блокировка автора.

**Правила и защита**
- В категориях «Университеты», «Районы» и «ЖК» можно состоять только в одном сообществе.
- Лимит сообщений против спама: не больше 5 за 10 секунд на пользователя.
- Фильтр запрещённых слов (мат и оскорбления, включая обход заменой букв).
- При удалении сообщения с фото файл удаляется и из Storage.
- Заблокированный пользователь теряет доступ сразу, не дожидаясь истечения токена.

## Быстрый старт

Нужны Node.js 20+, npm, pnpm и проект в Supabase (база и Storage).

**1. Backend**

```bash
cd backend
npm install
cp .env.example .env
npm run dev
```

Сервер запускается на `http://localhost:5000`. При старте он сам создаёт таблицы, индексы и стартовые данные, отдельных миграций запускать не нужно.

**2. Frontend**

```bash
cd frontend
pnpm install
```

Создайте `frontend/.env.local`:

```
NEXT_PUBLIC_API_URL=http://localhost:5000
```

```bash
pnpm dev
```

Сайт откроется на `http://localhost:3000`. Если frontend запущен на другом порту, укажите его в `FRONTEND_URL` у backend (это адрес для CORS).

## Переменные окружения (backend/.env)

| Переменная | Назначение |
|---|---|
| `PORT` | порт сервера (по умолчанию 5000) |
| `FRONTEND_URL` | адрес frontend для CORS и cookie |
| `DATABASE_URL` | строка подключения Postgres. Используйте Transaction pooler Supabase (порт 6543): прямое подключение работает только по IPv6 |
| `JWT_ACCESS_SECRET` | секрет access-токена (живёт 15 минут) |
| `JWT_REFRESH_SECRET` | секрет refresh-токена (живёт 7 дней) |
| `SUPABASE_URL` | Project URL из Supabase (Settings → API) |
| `SUPABASE_SECRET_KEY` или `SUPABASE_SERVICE_ROLE_KEY` | серверный ключ Supabase. Только на сервере, в git не попадает |
| `SUPABASE_BUCKET` | имя бакета (по умолчанию `chat-images`, создаётся при первой загрузке) |
| `GEMINI_API_KEY` | ключ для AI Summary |
| `GEMINI_MODEL` | необязательно, по умолчанию `gemini-flash-latest` |

Файлы `.env` и `.env.local` не коммитятся (см. `.gitignore`).

## База данных

Вся схема описана в `backend/src/plugins/pg.ts` и применяется при каждом запуске идемпотентно (`create ... if not exists`, `on conflict do nothing`). Удалять этот файл или выносить миграции нельзя без замены его другим механизмом.

Основные таблицы: `users`, `communities`, `community_members`, `rooms`, `messages`, `message_reactions`, `room_reads`, `message_clears`, `conversations`, `direct_messages`, `events`, `reports`, `report_events`.

При запуске добавляются стартовые данные: городские чаты, сообщества Бишкека (университеты, школы, районы, микрорайоны, жилмассивы, ЖК) с координатами и по 5 комнат у каждого. Для остальных городов (Ош, Джалал-Абад, Каракол, Токмок, Кара-Балта, Нарын, Талас, Баткен, Кант) добавлены по несколько вузов и колледжей, районов, школ и жилмассивов (список в `data/regionPlaces.ts`, координаты взяты с OpenStreetMap). Координаты примерные, точные можно поправить в админке: при перезапуске сервера они не затираются.

## Анонимность

- Другим пользователям показывается только `anon_id` (`Аноним #1234`), настоящие имя и почта в API сообщений не передаются.
- Имя из профиля видят только сам пользователь и администратор.
- Жалобы отправляются анонимно, автор сообщения не узнаёт, кто пожаловался.

## Как сделать пользователя администратором

Зарегистрируйтесь обычным способом, затем в Supabase (Table Editor → `users`) выставьте `is_admin = true`. После входа такой аккаунт попадает на `/admin` и в чат не пускается.

## API

Все маршруты, кроме регистрации, входа и списка сообществ, требуют заголовок `Authorization: Bearer <accessToken>`.

| Группа | Маршруты |
|---|---|
| `/auth` | `POST /register`, `POST /login`, `POST /refresh`, `POST /logout`, `GET /profile`, `PATCH /profile` |
| `/communities` | `GET /`, `GET /stats` (число сообществ и людей онлайн), `GET /mine`, `GET /discover`, `GET /:id`, `POST /:id/join`, `DELETE /:id/leave`; для админа: `GET /admin`, `POST /`, `PUT /:id`, `DELETE /:id` |
| `/messages` | `GET /`, `GET /pinned`, `GET /search`, `GET /read-state`, `GET /unread`, `POST /`, `POST /clear`, `POST /read`, `PATCH /:id`, `DELETE /:id`, `POST /:id/pin`, `POST /:id/forward`, `POST /:id/reactions`, `POST /:id/report` |
| `/conversations` | `GET /`, `POST /`, `GET /:id/messages`, `POST /:id/messages`, `POST /:id/accept`, `/decline`, `/block`, `/unblock`, `/read` |
| `/rooms`, `/events` | список, создание, изменение, удаление |
| `/uploads` | `POST /image` (JPG, PNG, WebP до 5 МБ) |
| `/summary` | `POST /:roomId` |
| `/users`, `/reports` | только для администратора |

**Socket.io.** Клиент подключается с access-токеном и входит в комнату `room:{id}`. События: `message:new`, `message:edited`, `message:pin`, `message:deleted`, `reaction:update`, `typing`; для личных сообщений `dm:message`, `dm:update`, `dm:read` и `room:unread` (клиент автоматически входит в свой канал `user:{id}`).

## Деплой

- **Frontend (Vercel):** корень проекта `frontend`, переменная `NEXT_PUBLIC_API_URL` с адресом backend.
- **Backend (Render):** корень `backend`, сборка `npm install && npm run build`, запуск `npm start`, все переменные окружения из таблицы выше. В `FRONTEND_URL` укажите адрес сайта на Vercel.
- Frontend и backend на разных доменах, поэтому в production refresh-cookie выставляется с `sameSite=none` и `secure`.
- Бесплатный тариф Render «засыпает», первый запрос после простоя может идти около минуты.

## Производительность

- Соединения с базой поддерживаются «тёплыми» (keep-alive и периодический пинг), поэтому после паузы первый запрос не тормозит.
- Данные пользователя для проверки токена (заблокирован ли, админ ли) кэшируются в памяти на 15 секунд; кэш сбрасывается при блокировке, удалении, входе и обновлении токена. Если выдать админа или заблокировать вручную в Supabase, изменение вступит в силу через несколько секунд или после повторного входа.
- Ответы API сжимаются (gzip), независимые запросы выполняются параллельно.
- Frontend запоминает последнее сообщество и комнату и загружает их сообщения одновременно с профилем.

## Известные ограничения

- Счётчик лимита сообщений хранится в памяти процесса: для одного экземпляра backend этого достаточно, при нескольких понадобится Redis.
- В комнате загружаются последние 50 сообщений, постраничной подгрузки старых пока нет.
- Фото, которые загрузили, но не отправили в сообщении, остаются в Storage. Фото удаляются при удалении сообщения пользователем.
- Автоматических тестов нет.
